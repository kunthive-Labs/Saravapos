Say it in their worldview.

An open protocol that translates ideas between mental models, so metaphors land and facts stay intact.

View on GitHub Install the CLI

Every explanation rides on shared metaphors.

A chess coach says "sacrifice a pawn for positional advantage" and another chess player nods, but a Formula 1 fan hears empty noise. The information is sound. The mental model behind it is missing.

LLMs can translate between languages and between codebases, but there was no portable, declarative way to say "render this idea for someone whose mental world looks like this." Saravapos closes that gap. You describe a worldview, its expertise, preferred analogies, cognitive style, and cultural references, as a small YAML profile. Given a from profile and a to profile, it swaps the metaphor layer while preserving the semantic payload. The translator never invents facts.

Two profiles in, one faithful rewrite out.

Saravapos translation schematic

@saravapos/spec

The protocol: profile shape as a JSON Schema

@saravapos/sdk

Translation from Node, TypeScript throughout

@saravapos/adapters

Anthropic, OpenAI, and local Ollama backends

@saravapos/cli

init, validate, and translate from the terminal

The implementation is a pnpm workspace of four packages, published to npm. Sample profiles ship in the repository: a chess expert, an F1 fan, a software engineer, and a curious novice.

The profile is the contract. The provider is replaceable.

persona profiles

A worldview is a file you can version

Profiles are small YAML or JSON files, validated against a JSON Schema. Author one once and reuse it everywhere, with no vendor tying it down.

worldview translation

Jargon expands or compresses to fit

Translation runs worldview to worldview. It expands jargon for novices and compresses it for experts, based on the expertise each profile declares.

analogy banks

Only the relevant metaphors get injected

Profiles carry their preferred metaphors. The dynamicAnalogy strategy extracts the concepts in your text and injects only the metaphors that match, deterministically, with no extra LLM call.

multi-provider

Bring your own key, or no key at all

Adapters ship for Anthropic, OpenAI, and local Ollama. Pick one at runtime and supply your own credentials, or run fully local.

cli + sdk

The terminal and Node both speak it

Run saravapos init, validate, and translate from the terminal, or call the same operations from @saravapos/sdk in Node.

eval harness

Quality is a CI gate, not a claim

Golden cases are scored by an LLM judge, strategies are compared A/B, and CI fails unless the corpus mean stays at or above 3.5.

Translating in two minutes.

Node 20 or newer. Install the CLI, author and validate a profile, then translate with your own API key.

saravapos - zsh
$ npm install -g @saravapos/cli $ saravapos init --output me.yaml && saravapos validate me.yaml $ export ANTHROPIC_API_KEY=sk-... $ saravapos translate --from profiles/chess-expert.yaml --to profiles/f1-fan.yaml \ --text "I sacrificed a pawn for a positional advantage"

Deliberately portable.

Saravapos ships no service. A worldview is a plain file, the protocol is a schema, and the model is whichever one you already have a key for or run on your own hardware.

Protocol-first

The profile format is defined by a JSON Schema, not by the reference implementation. Anything that reads and writes valid profiles interoperates.

Local-first

Profiles live on your machine as files you edit and version. No accounts, no servers, no telemetry.

Multi-provider

Anthropic, OpenAI, and Ollama adapters ship in the box. Swap providers without touching your profiles or your code.
