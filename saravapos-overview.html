01 · The Problem

Every explanation rides on shared metaphors. When the mental model is missing, the information vanishes — even if every word is technically correct.

Chess expert says
"I sacrificed a pawn for a positional advantage."
→
Formula 1 fan hears
[empty noise — no shared metaphor]

Today the fix is ad-hoc — the speaker rewrites by hand, or the listener gives up. LLMs can translate between human languages, codebases, and tones, but there is no portable, declarative way to say "render this idea for someone whose mental world looks like this."

02 · What Saravapos Does

Closes the metaphor gap. You describe a person's worldview as a small YAML profile. Given a from and to profile, Saravapos rewrites content so the metaphors land while the facts stay intact.

SOURCE — chess-expert.yaml
"I sacrificed a pawn for a positional advantage."
⇨
TARGET — f1-fan.yaml
"I burned an extra pit stop to undercut the leader and take track position."
P

Protocol-first

A JSON Schema defines what a profile is. Anyone can implement against it — SDKs, CLIs, editor plugins.

L

Local-first

Profiles are plain YAML files you own. No accounts, no servers, no telemetry. Version-controllable.

M

Multi-provider

BYOK — bring your own LLM key. Anthropic, OpenAI, or Ollama (local). Swap at runtime.

C

CLI + SDK

Use saravapos from the terminal, or @saravapos/sdk from a Node app.

03 · How It Works

A translation call always takes two profiles. The SDK lowers both into a system prompt, sends the source text as user input, and the chosen LLM rewrites.

Step 1
Load profiles
Read YAML from disk. Validate against JSON Schema. Throw ProfileValidationError with field path on bad shape.
→
Step 2
Build prompt
A PromptStrategy renders both profiles into a system prompt: identity, expertise, analogy bank, cognitive style, cultural context.
→
Step 3
Call adapter
Adapter (Anthropic/OpenAI/Ollama) sends the prompt at chosen temperature, retries on 429, surfaces typed AdapterError.
→
Step 4
Return text
Raw translated text. Caller writes to stdout, file, or further pipelines.

04 · Architecture

A small pnpm-workspace monorepo. Five packages, layered so the protocol is independent of the SDK, the SDK is independent of any specific provider, and the CLI is a thin shell over the SDK.

protocol (spec) core library (sdk) provider plugins (adapters) user interface (cli) quality harness (eval, private)

05 · The 5 Packages

Each package has a single responsibility, lives in packages/<name>, and is published as @saravapos/<name> (except eval, which stays private).

Package Role Key exports Published?

06 · Profile Schema (v0.1)

A profile is a YAML document with one required header + five fields describing the persona. Only schema_version and identity are required; everything else is optional but recommended.

Example: a full profile

schema_version: '0.1'

identity:
  display_name: 'Jordan'
  languages: ['en']
  region: 'UK'

expertise:
  - domain: 'formula-one'
    level: 'expert'
    years: 15
  - domain: 'chess'
    level: 'novice'

analogy_bank:
  - concept: 'sacrificing a pawn for positional advantage'
    metaphor: 'burning an extra pit stop to undercut the leader'
    domain: 'formula-one'
  - concept: 'opening theory'
    metaphor: 'qualifying setup'
    domain: 'formula-one'

cognitive_style:
  mode: 'verbal'
  prefers:
    - 'concrete examples'
    - 'step-by-step'
  abstraction_tolerance: 'medium'

cultural_context:
  references_that_land:
    - 'Premier League'
    - 'cricket'
    - 'BBC'
  references_to_avoid:
    - 'NFL'
    - 'NASCAR'

Field-by-field semantics

Field Required How a translator uses it
identity.languages[0] yes Defines the output language. region is advisory — biases idioms/units but never changes facts.
expertise no Compares from vs to levels per domain. Lower → expand, define, slow down. Higher → compress, use shorthand.
analogy_bank no Translator prefers entries from to.analogy_bank before inventing. Lookup is case-insensitive substring on concept.
cognitive_style no mode + prefers shape format (prose vs. bullets, diagrams vs. paragraphs). abstraction_tolerance shapes phrasing.
cultural_context no references_that_land is a shortlist to reach for. references_to_avoid is a soft filter — skip these phrases.
Versioning policy: schema_version follows semver-style discipline. While in 0.y, any bump may break. Profiles MUST pin the version they were authored against; loaders MUST reject unknown versions. Current: 0.1.

08 · LLM Adapters

A small LLMAdapter interface (name + complete()) plus three first-party implementations. Pick via resolveAdapter(name) or the CLI --provider flag. BYOK — no provider is ever hardcoded.

Provider name Env var Default model Transport
Anthropic anthropic ANTHROPIC_API_KEY claude-sonnet-4-6 @anthropic-ai/sdk · messages.create
OpenAI openai OPENAI_API_KEY gpt-4o openai · chat.completions.create
Ollama ollama OLLAMA_HOST (optional) llama3.1 HTTP POST → localhost:11434/api/chat

The adapter contract

interface LLMAdapter {
  name: string;
  complete(opts: {
    system: string;
    user: string;
    model?: string;
    temperature?: number;
  }): Promise<{ text: string }>;
}

All failures throw a typed AdapterError carrying provider, optional HTTP status, and cause. A single-retry backoff handles 429s. Missing API keys fail synchronously at construction.

09 · CLI Reference

The saravapos binary. Five subcommands. Friendly red error messages on validation/adapter failures with the failing field path quoted.

Command What it does
saravapos translate Translate text between two profiles. Source via --text, --input <file>, or stdin (exactly one). Output to stdout or --output <file>.
saravapos validate <path> Validate a profile YAML against the schema. Green check on success; red field errors + non-zero exit on failure.
saravapos init -o <path> Interactive wizard (inquirer prompts). Asks identity + ≥1 expertise entry, writes a well-commented template. Refuses to overwrite without --force.
saravapos list-providers Prints supported adapters, env vars, default models.
saravapos version Same as --version. Reads from the package manifest.

Translate — example invocations

# inline text
saravapos translate \
  --from profiles/chess-expert.yaml \
  --to   profiles/f1-fan.yaml \
  --text "I sacrificed a pawn for positional advantage"

# read a file, write a file
saravapos translate \
  --from profiles/software-engineer.yaml \
  --to   profiles/curious-novice.yaml \
  --input notes.md \
  --output notes.translated.md

# stdin pipe, switch provider and model
echo "Recursion is the soul of induction." | saravapos \
  --provider openai \
  translate \
  --from profiles/software-engineer.yaml \
  --to   profiles/curious-novice.yaml \
  --model gpt-4o

10 · SDK API

Two exports do the work: loadProfile (parse + validate YAML) and translate (drive any adapter end-to-end).

loadProfile

import { loadProfile } from '@saravapos/sdk';

const from = await loadProfile(
  'profiles/chess-expert.yaml'
);

// Throws ProfileValidationError with the
// failing field path if YAML doesn't match
// the schema. Throws on missing file too.

There's also loadProfileFromString(yaml) for tests and URL fetches.

translate

import { translate } from '@saravapos/sdk';
import { resolveAdapter } from '@saravapos/adapters';

const out = await translate({
  text: 'I sacrificed a pawn...',
  from,
  to,
  adapter: resolveAdapter('anthropic'),
  // optional:
  model: 'claude-opus-4-7',
  temperature: 0,
});

Returns the raw translated string. Pipe it anywhere.

Error types

Error Thrown by Carries
ProfileValidationError loadProfile / loadProfileFromString Failing JSON-pointer field path, ajv message
AdapterError any adapter .complete() provider, optional HTTP status, cause
CaseValidationError eval loadCase Failing field path on golden-case YAML
JudgeParseError eval judge() Raw judge response (truncated) for inspection

baseline

2

structured

packages/sdk/src/prompts/strategies/structured.ts

12 · Eval Harness

A repeatable signal on translation quality, so prompt tuning and analogy injection are driven by data, not vibes. Lives in packages/eval — private, never published.

Inputs
Golden cases
9 YAML files in packages/eval/cases/: from/to profile paths, input text, named rubric criteria, optional must_include/must_avoid.
→
Run
Translate
Calls sdk.translate() at temperature: 0. Cached on disk by sha256(provider+model+system+user).
→
Score
LLM judge
An adapter call (default claude-sonnet-4-6) returns strict JSON: per-criterion 1–5 score + one-line reasoning. Weighted into overall.
→
Check
Lexical + Gate
must_include/must_avoid regex checks fold into passedLexical. CI gate: mean ≥ 3.5, no case < 3.

The 9 golden cases

Case ID Direction Probes
chess-to-f1-pawn chess-expert → f1-fan Pawn-sacrifice analogy translation (seed case)
chess-to-f1-initiative chess-expert → f1-fan Translating "initiative" between domains
chess-to-novice-checkmate chess-expert → curious-novice Jargon stripping
chess-to-novice-endgame chess-expert → curious-novice Concept expansion + concrete examples
f1-to-chess-undercut f1-fan → chess-expert Reverse direction
novice-to-swe-backup curious-novice → software-engineer Abstraction raising
swe-to-f1-hotpath software-engineer → f1-fan Cross-domain analogy (perf jargon → racing)
swe-to-novice-memleak software-engineer → curious-novice Has must_avoid assertions
swe-to-novice-refactor software-engineer → curious-novice Edge-case (terse / single-word input)

Report format

case                              over  lex   time
--------------------------------------------------
chess-to-f1-pawn                   4.0  pass  812ms
chess-to-novice-checkmate          3.5  pass  640ms
...
mean=3.94  min=swe-to-novice-memleak (3.0)  lexical=89%
cases=9

Run flags

Flag Default What it does
--cases <dir> packages/eval/cases Directory of golden case YAML files
--provider <name> anthropic Translation provider
--judge-model <m> claude-sonnet-4-6 Override the judge model
--threshold <n> — Mean overall floor — exit non-zero below it
--min-case <n> — Per-case floor — exit non-zero if any case below
--baseline <file> — Compare against saved scores; reports cases that dropped > 0.5
--write-baseline <file> — Snapshot current scores to file
--no-cache off Force fresh adapter calls
--json <file> — Write machine-readable report

Exit codes: 0 clean · 1 quality gate failed · 2 infra (judge returned non-JSON).

Important: eval-baseline.json currently ships as a placeholder seed — all scores are 0. The CI eval job runs but cannot flag regressions until you regenerate it with a real key: ANTHROPIC_API_KEY=sk-... pnpm eval run --write-baseline eval-baseline.json.

15 · Known Defects

From PROGRESS.local.md — verified against working tree.

#1 · pnpm -r test fails

Per-package test script is vitest run --dir src, but the root vitest include glob is packages/*/src/**/*.test.ts. Inside a package the glob matches nothing → exit 1.

Workaround: tests only pass from repo root (npx vitest run → 89/89). Because prepublishOnly calls pnpm run test, a real publish would break until fixed.

#2 · CHANGELOG out of sync

CHANGELOG "Known limitations" says analogy_bank is "parsed but not yet injected" — but packages/sdk/src/prompts/system.ts:33 already dumps up to 8 entries verbatim into the system prompt. Stale note.

#3 · eval-baseline.json is a placeholder

All scores are 0 (out of the 1–5 range). The CI eval gate runs but won't flag regressions until you regenerate the baseline with a real API key.

Fix: ANTHROPIC_API_KEY=sk-... pnpm eval run --write-baseline eval-baseline.json

#4 · npm publish unverified

The Day-14 tag v0.1.0-alpha.0 exists locally, but there's no git evidence that the manual pnpm publish ran. Verify with npm view @saravapos/cli version before claiming the alpha is live.

16 · Getting Started

Three ways in: the CLI, the SDK, or running the eval harness yourself.

1 · Install the CLI

# global
npm install -g @saravapos/cli@alpha

# or per-project
pnpm add @saravapos/sdk @saravapos/adapters

Requires Node 20+.

2 · Author + validate a profile

# interactive wizard
saravapos init --output me.yaml

# check the spec
saravapos validate me.yaml

3 · Translate something

export ANTHROPIC_API_KEY=sk-...

saravapos translate \
  --from profiles/chess-expert.yaml \
  --to   profiles/f1-fan.yaml \
  --text "I sacrificed a pawn for a positional advantage"

4 · Use the SDK directly

import { loadProfile, translate } from '@saravapos/sdk';
import { resolveAdapter } from '@saravapos/adapters';

const from = await loadProfile('profiles/chess-expert.yaml');
const to   = await loadProfile('profiles/f1-fan.yaml');

const adapter = resolveAdapter('anthropic'); // reads ANTHROPIC_API_KEY

const out = await translate({
  text: 'I sacrificed a pawn for a positional advantage',
  from, to, adapter,
});

console.log(out);
// → "I burned an extra pit stop to undercut the leader..."

5 · Run the eval harness

# needs ANTHROPIC_API_KEY for the judge
pnpm eval run

# with the CI quality gate
pnpm eval run --threshold 3.5 --min-case 3 --baseline eval-baseline.json

# snapshot a new baseline
pnpm eval run --write-baseline eval-baseline.json
